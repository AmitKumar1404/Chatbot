INTERVIEW PREPARATION
Branch: feature/qwen2.5-model-upgrade

PROJECT CONTEXT
Commit `dd49b14` ne default Ollama model `${OLLAMA_MODEL:qwen2.5:7b}` kiya, whitespace-only streamed fragments preserve kiye, aur assistant output ko ReactMarkdown `10.1.0` + remark-gfm `4.0.1` se render kiya. Endpoint aur database contract unchanged rahe.

SECTION 1 — BASIC INTERVIEW QUESTIONS

Q1. LLM streaming me token/chunk kya hota hai?

Answer:
Model response incremental fragments me aata hai; chunk lexical token ke equal hona zaroori nahi aur whitespace-only bhi ho sakta hai.

Follow-up Q1.1: Chunk boundaries par Markdown parse karna safe hai?

Answer:
Individual chunk incomplete syntax ho sakta hai. Project accumulated message render karta hai; backend fragments ko order aur exact whitespace ke saath forward karta hai.

Q2. NDJSON kya hai?

Answer:
Newline-delimited JSON: har line independent JSON object hoti hai, streaming parser line-by-line process kar sakta hai.

Q3. Whitespace Markdown me semantic kyun hai?

Answer:
Newlines, indentation aur blank spacing lists, tables, paragraphs aur code fences ki structure carry karte hain.

Q4. ReactMarkdown aur remark-gfm kya roles play karte hain?

Answer:
ReactMarkdown Markdown AST ko React elements me render karta hai; remark-gfm tables, task lists, strikethrough jaise GFM syntax add karta hai.

Follow-up Q4.1: Search highlight Markdown path kyun bypass karta hai?

Answer:
Existing highlighted output React nodes with `<mark>` banata hai; commit active search target ke liye wahi plain-text path preserve karta hai.

Q5. Backpressure/cancellation streaming me kyun matter karte hain?

Answer:
Slow/disconnected client ke baad unnecessary parsing/emission avoid karni hoti hai; ordered bounded processing resource waste reduce karta hai.

SECTION 2 — PROJECT-SPECIFIC INTERVIEW QUESTIONS

Q6. Backend parser me exact behavior change kya hua?

Answer:
Old `.filter(text -> !text.isBlank())` hata. Successfully parsed, non-null response strings me whitespace preserve hoti hai; `done=true` plus empty response emit nahi hota. Missing/null `response` no fragment deta hai, aur malformed JSON parse error path se bhi fragment emit nahi hota.

Q7. Model configuration exact kya hai?

Answer:
Default `${OLLAMA_MODEL:qwen2.5:7b}` hai, so environment override possible hai.

Q8. Search-highlight case Markdown se alag kyun hai?

Answer:
Active assistant search match existing plain-text `<mark>` rendering use karta hai; other assistant content ReactMarkdown/GFM se render hota hai.

SECTION 3 — WHY / WHY NOT QUESTIONS

Q9. Har blank chunk drop karna kyun wrong tha?

Answer:
`isBlank()` spaces/newlines/tabs sab drop karta hai. Stream concatenate hone par Markdown structure collapse ho sakti hai.

Q10. Raw HTML directly render kyun nahi kiya?

Answer:
ReactMarkdown structured renderer safer default boundary deta hai; arbitrary HTML enabling separate sanitization decision mangta hai.

SECTION 4 — HOW DOES IT WORK?

Q11. Ollama line se UI tak flow trace karo.

Answer:
WebClient NDJSON line deta hai → ObjectMapper `response`/`done` parse karta hai → ordered Flux text emit karta hai → frontend accumulated assistant content ReactMarkdown/GFM render karta hai.

Q12. Terminal frame kaise identify hota hai?

Answer:
`done` boolean true aur response empty ho to parser `Flux.empty()` return karta hai; nonterminal whitespace retained hai.

SECTION 5 — FOLLOW-UP QUESTIONS

Q13. Copy button rendered HTML copy karta hai?

Answer:
Nahi. Branch comment/flow raw `msg.content` ko copy source rakhta hai; Markdown rendering presentation layer hai.

Q14. `visualize()` helper kyun add hua?

Answer:
Debug logs me carriage return/newline/tab visible escape form me dikhane ke liye; it does not alter emitted content.

SECTION 6 — WHAT-IF / EDGE CASE QUESTIONS

Q15. Response field missing/null ho to?

Answer:
Parser text null set karke no fragment emit karta hai.

Q16. Malformed NDJSON middle me aaye to?

Answer:

Q17. Whitespace flood ka risk kya hai?

Answer:
Semantics preserve karna necessary hai, but pathological whitespace extra network/render/log work kara sakti hai; bounded metrics and tests useful hain.
