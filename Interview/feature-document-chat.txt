SECTION 1 — BASIC INTERVIEW QUESTIONS
===============
Q1. RAG kya hai?
Answer: Retrieval-Augmented Generation me user question ke relevant source chunks retrieve karke model prompt me context diya jata hai. General benefit factual grounding hai; project PDF chunks par hybrid retrieval karta hai. Potential improvement: retrieval/output evaluation aur citations.

Follow-up Q1.1. Fine-tuning se difference?
Answer: Fine-tuning model weights change karta hai; RAG runtime external knowledge inject karta hai. Documents update karna RAG me cheaper hai.

Q2. Branch exactly kya add karti hai?
Answer: Synchronous PDF upload, extraction, chunking, embeddings persistence, cosine+BM25 retrieval, bounded context, grounded prompt aur DOCUMENT chat routing.

Q3. PDF limit kya hai?
Answer: 25 MB constant. Empty, non-.pdf filename, non-application/pdf MIME aur over-limit file reject hoti hai.

Q4. Dedupe kaise?
Answer: Raw PDF bytes ka SHA-256 banta hai. Repository precheck aur V12 global unique file_hash duplicate prevent karte hain.

Follow-up Q4.1. Per-user dedupe hai?
Answer: Nahi, global. Same bytes dusra user bhi upload nahi kar sakta.

Q5. Embeddings kaha store hote hain?
Answer: V11 me JSONB column, one embedding row per chunk via unique chunk_id. pgvector/vector index nahi.

Q6. Retrieval signals?
Answer: Dense cosine semantic similarity aur sparse BM25 lexical relevance; configured weighted fusion.

SECTION 3 — WHY / WHY NOT QUESTIONS
=====================
Q15. Synchronous upload kyun?
Answer: Implementation simple aur immediate ready response deta hai. Trade-off request latency, timeout aur partial side effects. Production improvement async job/status pipeline.

Q16. PDFBox kyun?
Answer: JVM-native PDF text extraction existing Spring stack me fit hoti hai. OCR-scanned PDFs ke liye insufficient ho sakti hai; OCR pipeline evidence N/A.

Q17. Chunking kyun?
Answer: Full PDF prompt/token budget exceed karta aur retrieval precision dilute hoti. Chunking local relevant context select karta hai.

Q18. Overlap kyun?
Answer: Boundary par split concept continuity preserve hoti. Excess overlap duplicates/context cost badhata; builder dedupe exact normalized duplicates only.

Q19. Hybrid retrieval kyun?
Answer: Dense synonyms/semantics pakadta, BM25 exact terms/acronyms. Fusion complementary recall improve kar sakti hai; quality benchmark evidence N/A.

Q20. JSONB kyun, pgvector kyun nahi?
Answer: JSONB simple persistence tha; current Java scoring implementation se compatible. Scale par all-vectors load bottleneck hai, pgvector/HNSW candidate search better.

Q21. SHA-256 filename dedupe se better kyun?
Answer: Rename hone par same bytes detect hote hain; same filename different content allow ho sakta hai. Hash content identity hai, document semantics identity nahi.

Q22. Explicit mode kyun?
Answer: Stale documentId ko implicit RAG activation se rokta aur user intent clear karta. Missing mode NORMAL default hona backward compatible hai.

SECTION 4 — HOW DOES IT WORK?
==========================
Q23. Upload API flow trace karo.
Answer: React multipart upload → POST effective /api/v1/api/documents/upload → authenticated principal → service validation/copy/extract/chunk/embed/persist → DocumentUploadResponse → selected document state.

Q24. Effective path double prefix kyun?
Answer: Context /api/v1 plus controller /api/documents/upload concatenate hoke /api/v1/api/documents/upload.

Q25. Query-time flow numbered?
Answer:
1. STOMP payload principal authenticate.
2. mode resolve.
3. DOCUMENT requires document ID.
4. existsByIdAndUploadedBy_Username ownership check.
5. query embedding.
6. document vectors/chunks load.
7. cosine+BM25 rank.
8. bounded context.
9. grounded prompt + history.
10. chunk/done/error events stream.

Q26. Cosine formula?
Answer: dot(A,B)/(||A||*||B||). Dimension mismatch throws; zero norm returns 0.

Q27. BM25 basics?
Answer: Term frequency saturation k1, inverse document frequency aur length normalization b use hote hain. Project in-memory candidate corpus ke chunk contents par calculate karta hai.

Q28. Fusion normalization?
Answer: `maxCosineScore > 0` hone par cosine score maximum se divide hota hai; otherwise normalized vector score zero hota hai. `maxBm25Score > 0` hone par BM25 score maximum se divide hota hai; otherwise normalized keyword score zero hota hai. Phir `vectorWeight * normalizedCosine + keywordWeight * normalizedBm25` fusion hota hai.

Q29. Tie-breaking?
Answer: Hybrid descending, then raw cosine descending, then chunkIndex ascending; deterministic output.

Q30. V12 migration flow?
Answer: `file_hash` nullable add hota hai, named unique constraint guarded block me banti hai, legacy NULL precondition check hota hai, phir NOT NULL enforce hota hai. Migration fake hash invent nahi karti. Operator ko legacy NULL rows ke liye either real-byte hash backfill ya documented deletion/cleanup path choose karna padta hai before rerun.
