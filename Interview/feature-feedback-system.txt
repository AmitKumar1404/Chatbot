SECTION 1 — BASIC INTERVIEW QUESTIONS
===============
Q1. Message feedback feature kya solve karta hai?
Answer: User har completed assistant message ko HELPFUL ya NOT_HELPFUL mark kar sakta hai. General concept quality signal collect karna hai; project me signal user-message pair par persist hota hai aur history me selection restore hoti hai. Potential improvement: feedback ko model/version, latency aur prompt metadata se correlate karke quality analysis richer ho sakta hai.

Follow-up Q1.1. Session-level rating kyun nahi?
Answer: Message-level rating exact bad response identify karta hai. Session rating simpler hoti, lekin kis answer me issue tha woh lose ho jata.

Q2. Branch lineage ka precise answer kya hai?
Answer: 9d27224 se 1c3e913 tak implementation main me PR #33 se merged hai. 4185ea6 main ka part nahi; use current-main behavior bolna factually wrong hoga.

Follow-up Q2.1. Tip-only delta kya hai?
Answer: NOT_HELPFUL reason requirement/validation, history DTO me reason restoration aur malformed feedbackReason ke controlled 400 handling ka stricter patch.

Q3. Feedback ke core enums kya hain?
Answer: MessageFeedbackType me HELPFUL aur NOT_HELPFUL. FeedbackReason separate enum hai. V7 type ko DB CHECK se bound karta hai; V8 reason column add karta hai, lekin reason ka DB CHECK nahi.

Q4. Upsert ka meaning kya hai?
Answer: Same user aur same message par first request insert, later request existing row update karti hai. Project implementation pehle find karti hai, phir entity create/update karke save karti hai.

Follow-up Q4.1. Kya yeh atomic database upsert hai?
Answer: Nahi. Yeh read-then-write application upsert hai; concurrent first inserts me race ho sakti hai. Unique constraint final invariant hai, graceful conflict handling nahi.

SECTION 3 — WHY / WHY NOT QUESTIONS
=====================
Q11. Separate feedback table kyun?
Answer: General concept me feedback user-specific relation hai, Message ka single scalar nahi. Project me same message/user uniqueness, timestamps aur future metadata isolate hote hain. Potential improvement: audit/history chahiye to overwrite ke bajay append-only events rakhe ja sakte hain.

Q12. Message entity me helpfulCount kyun nahi?
Answer: Counter source-of-truth lose karta, per-user update/authorization difficult hoti aur decrement/change race aati. Derived aggregate safer hai, though large scale par materialized aggregate useful ho sakta hai.

Q13. PUT kyun, POST kyun nahi?
Answer: User-message pair ka desired state replace/update hota hai, so idempotent intent ke liye PUT suitable hai. Current read-then-write race ki wajah se implementation-level idempotency perfect nahi.

Q14. Optimistic UI kyun?
Answer: Feedback action low-latency feel hota hai. Project rollback failure consistency restore karta hai. Potential improvement: request version/AbortController se out-of-order responses guard karna.

Q15. Reason HELPFUL par null kyun?
Answer: Current domain reasons negative-quality categories hain. Stale negative reason ko HELPFUL switch par clear karna contradictory state prevent karta hai.

Follow-up Q15.1. Positive reason future me chahiye to?
Answer: Reason taxonomy ko sentiment/type-compatible mapping ya separate positive/negative enums me model karunga.

Q16. Analytics controller ko admin naam dena enough kyun nahi?
Answer: URL naming authorization nahi hoti. SecurityConfig me authority/role rule ya method-level @PreAuthorize chahiye.

SECTION 6 — WHAT-IF / EDGE CASE QUESTIONS
======================
Q28. Do simultaneous first submissions aaye to?
Answer: Dono find me empty dekh sakte hain; ek insert win karega, doosra V7 unique constraint violate kar sakta hai. Improvement: INSERT ... ON CONFLICT DO UPDATE aur conflict-specific response.

Q29. Same feedback rapid double-click?

Q30. Out-of-order update responses?
Answer: Request A aur B overlap karein to slower A UI/server state ko surprising bana sakta hai. Current code me request sequence evidence nahi; improvement latest-request token ya disable-until-complete.

Q31. Message request ke baad delete ho jaye?
Answer: FK/cascade and transaction ordering par save fail/not-found ho sakta hai. Controlled 404/409 mapping better hoga; current RuntimeException broadly 400 map hoti hai.

Q32. Feedback row ke baad message/user delete ho?

Q33. Invalid feedbackType string aaye?

Q34. NOT_HELPFUL without reason?

Q35. HELPFUL with reason?
